# 约5分钟的代码与软件展示脚本

## 0:00—0:40 说明环境

“这里是设备状态监测的合成工业环境：一台电机、一套循环泵背景设备，后端使用Linux、Windows与VxWorks节点画像。采集、预处理、检测和告警有不同平台版本。界面容量条表示资源预留。”

指出顶部“合成环境 / Java + CloudSim”，不要说已经部署了真实三系统容器或RTP。

## 0:40—1:20 展示算法与方案

指出四个服务所在节点、备用节点、CPU/RAM预留，以及CloudSim传输/启动/就绪事件。
打开本轮project中的ScenarioLoader、CompatibilityChecker、BeamSearchPlanner和PlanRuntime，说明配置→兼容检查→规划→部署事件的代码路径，不逐行朗读全部代码。

## 1:20—2:50 注入节点故障并恢复业务

选择当前采集服务所在节点离线。观察该节点变为离线，上下游业务变为阻断。
点击诊断，区分NODE_OFFLINE和UPSTREAM_UNAVAILABLE。再执行修复，显示节点恢复在线、重新计算的资源预留和新部署事件；迁移与否按实际方案如实展示。
展示目标节点恢复上线、驱动/运行环境恢复，最后验证业务链。节点统一显示在线；再次对同一节点注入故障，证明它可反复参与测试。

## 2:50—4:00 展示工艺故障

上一轮恢复验证通过后直接切换到电机过热并注入，也可按需重置。温度越过80°C，服务可以仍然正常部署。诊断为工艺温升，执行模拟冷却，推进采样，连续正常后验证。
指出工艺异常与部署异常的处理方法不同：前者冷却和观察，后者约束检查与重新部署。

## 4:00—5:00 展示验证证据与边界

展示已完成故障类型与累计轮次，再导出包含多轮诊断和迁移的演练记录；打开配置校验报告，展示100项检查和精确反例：更多服务不一定带来更多完整业务链。
说明当前精确解只覆盖固定拓扑/FIFO次序下的小规模接纳与放置；后续再进行真实平台及更广场景验证。

演示前检查：仅保留一个页面；浏览器最大化/F11；服务终端保持开启；准备从正常状态开始；无需联网。出现问题可先保存记录再重置，不必现场修改原Java源码。
